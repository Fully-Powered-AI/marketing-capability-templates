# Lead magnet plan: tried on its invented example

- **Product:** Claude, run in Claude Code
- **Model:** Claude Opus 5.5 (model ID claude-opus-5-5)
- **Date:** 2026-11-09

The inputs are the invented example in `public/example.md` (an invented IT support firm for small architecture practices). No client data was used. The run followed the instruction block in `member/template.md` and its output format, as revised on 9 November 2026 after an earlier run and an independent review (both described at the end). This run was made by the same session that revised the template and the example, and that session had read the example's own output beforehand, so it is not a blind comparison.

## Inputs used

The inputs in `public/example.md`, section "The inputs", as revised: your facts, hours and forms, the five-line question log with the default headers, what already exists, the one proposed idea, and the settings, which now include a date of the plan (4 November 2026).

## What was observed

- Every part of the output format was produced, in order. Nothing in the run told the assistant to stop: the facts, headers and hours were all present, there was no instruction hidden in a source, and no password or code appeared.
- The result matches the published example in the verdict, the chosen question and its three sources, the reader, the moment, the format, the hours, the runner-up, the date, the delivery decision, all five checks, the limits, the decisions and the five items left out. The two differ in wording, in the title, and in the outline: this run has six sections (backups separate from files and archive), the example has five. Both are consistent with the template, which leaves the number of sections to the assistant.
- The revised rules each settled a point the earlier run had to guess: the moment clause placed "before we switch" at ready to start; the "partly" clause kept the group at "nothing" while section 4 names the backups article under "Draws on"; the checklist line says "to be written: the two lines per item"; the partner's "how" became a section naming what to ask for, with the refusal case under Left out; the idea rule gave the ebook its reason.
- One wording the moment clause does not name: the partner's "If we leave our current provider..." is conditional, neither plainly "before we switch" nor plainly asking whether to switch. The group's other two questions sit at ready to start, so the majority rule decided it and the result did not depend on it.
- Every "Gives" line in this run traces to an item in the material on hand or to the partner's question; nothing numeric, no client name and no result was added.
- This was one run by one model on one example, made by the session that had revised the template and read the example's output. It shows the template can be followed to a complete, coherent plan on this input. It does not show how it behaves on other inputs, and it is not a test in a client environment.

## The earlier run and what changed after it

An earlier run on the same day, with Claude Sonnet 5.5 in Claude Code on the unrevised template and example, also produced a complete plan with the same verdict, question, reader, format and form decision. Its record noted places where the instructions left room to guess: how to place a question about preparing for a decision already taken; whether a published piece covering one item makes a group "partly" answered; a how-to question inside a checklist; whether "to be written" satisfies the rule for the two lines per checklist item; and no test for judging a proposed idea. It also noted that the example's section notes added reasons not in the inputs, and that its own date came from the day of the run because the inputs gave no date for the plan. An independent review then asked for the same points. The template now has one clause for each, a date of the plan among the settings, and the example's "Gives" lines and opening trimmed to what the inputs hold; this run is on that revised version.

## Small changes made after this run

After a second independent review, the instruction block and procedure were given three wording changes that were not re-run: the moment clause now places a conditional question that assumes the decision ("if we leave, how do we...") at ready to start, which closes the open point noted above; the runner-up rule now says "whether or not it fits the hours"; and the instruction block now carries two rules the procedure already had, the "no buyer question heard: [approver role]'s choice" wording and returning the plan to the approver only. On this example none of them changes the result recorded above: the group's moment was already ready to start, the runner-up was already named for the hours, and no choice had been made in advance. The example's promise was also reworded from "everything to collect" to "the items to collect", the wording this run used.

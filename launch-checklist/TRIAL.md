# Launch checklist: tried on its example

- **Product:** Claude, run in Claude Code
- **Model:** Claude Sonnet 5.5 (model ID claude-sonnet-5-5)
- **Date:** 2026-11-09

The inputs are the invented example in `public/example.md` (Quillfern Bookkeeping, an invented firm); no client data was used. The run was made by a model that did not write the template. It read the template and only the inputs section of the example (the eight inputs: launch brief with size answers, facts, team, audience list, where the launch stands, hosts' dates, earlier launches, existing material), followed the instruction block and the output format, produced the output, and only then read the example's published output to compare. One run, one product.

**Edited after this run, 9 November 2026.** Following the independent review, the template and the published example were edited after the run recorded here, and the run was not repeated. The template's procedure and instruction block gained these sentences: a group the launch is for is one whose members are in the audience the brief names, and a group that only passes the launch on, such as partner firms, is a borrowed channel (shortcoming 4); work split across two roles becomes two lines on the same date (shortcoming 6); the writer of each draft revises it after the fresh reader's list (shortcoming 3); the host line carries its own go, and the D-1 approval covers the day's drafts only (shortcoming 2); the D-1 page check reads "the page, as it will be published, is not set to stay out of search results" (shortcoming 1); and on a first run the last version is not listed under "Not supplied" (shortcoming 10). Three rules already in the procedure were added to the instruction block so that it stands alone: Monday to Friday when the working days are missing, a paid channel only with a budget and an owner, and no draft line from two inputs that disagree. The output format and the example's inputs did not change. The published example's output was edited the same day: the association send line now reads "To: restaurant owners' association members, about 400, through the newsletter's editor" in place of "the editor, 1"; the check that the association piece appeared (A2) and the line taking unclear-page questions to the office manager (A3) are "not assigned", with a question each, making three questions; the test booking is no longer cancelled and the personal notes are no longer sent "one at a time"; and the association piece is marked as revised after the fresh reader. The output and observations below are as recorded, so the differences they list refer to the example as it stood before these edits.

## What was observed

Every part the output format asks for was produced: header, size line with spacing, readiness with three tests and stalls, channels with the reasons for those not used, the dated checklist, drafts needed, what the launch makes wrong, changes since the last version, questions, and the closing line. No stop condition was triggered: all required inputs were present, the audience list had the default headers, and nothing in the inputs read like an instruction to the assistant. Every date was checked against the calendar (D is a Thursday; the Saturday D-5 moved to Friday 13 November; D+7 fell on the closed Thursday 26 November and moved to Monday 30 November, counted as D+11).

Differences from the published example:

- Line count: 20 lines against the example's 19. The template says one line has one owner, so the changes to live pages (office manager) and to the sales one-pager (owner) became two lines. The example has one line owned by the owner.
- Owner of the check that the association piece appeared: the example gives it to the owner; this run wrote "not assigned" because no role in the team note covers it, as the template's rule says, and asked a question.
- To-whom on the association send line: this run used the group and count from the audience list (about 400 members, through the editor). The example says "the editor, 1", a count that is not on the audience list.
- Questions: 7 here against 1 in the example. The extra six are about the nine restaurant clients, the one-pager's maker and old copies, the unassigned check, the choice of borrowed channel, the approval timing of the association piece, and time to revise after the fresh reader. The one shared question is the free first month.
- Details in the example that this run did not produce: the test booking is cancelled afterwards; the monthly report sample link is checked; the page check notes that no social network is used so no in-app browser needs checking; replies are written one at a time. Details this run added: the replacement one-pager has its own line, and the prepared changes are read by the fresh reader.
- Readiness, size, spacing, channels, the five outward lines, dates, drafts needed and "what this launch makes wrong" agree in substance with the example.

Facts not in the inputs:

- This run: it states that the association editor places the piece in the 23 November issue (the inputs give only the deadline and the issue date), and it names the sources the enquiries sheet records (personal note, email list, association newsletter, direct to the page), which are inferred from the channels. Both are small.
- The example: "the editor, 1" (a count the audience list lacks), cancelling the test booking, sending notes "one at a time", and giving the association check to the owner although the team note does not cover it.

Ambiguities and shortcomings in the template met on this run:

1. The page check on the day before the launch (D-1) speaks of "the live page" and its search settings, but the page is not published until D. The check can only be made on the draft or a preview, and the template does not say so.
2. The line that sends material to a borrowed host falls on the host's deadline, which can be before the D-1 line where the approver approves the outward drafts. Both lines are outward, so each waits for the approver's go, but the D-1 line then looks like the only approval. This run wrote the go onto the host line itself.
3. Nothing in the procedure books time to revise drafts after the fresh reader's list, although the host's deadline may follow it by one working day.
4. "Groups the launch is for" is not defined when a current-client group is part of the audience (the nine restaurant clients) or when a group is an intermediary (two partner firms). The run had to guess and asked.
5. "To: the group and count from the audience list" does not fit a send to a host's editor, who is one person while the audience is the host's list.
6. The "one line, one owner" rule meets work split across roles (page changes by the office manager, the one-pager by the owner); the template does not say whether to split the line.
7. Nothing covers copies of an old document already in circulation (the one-pager already handed to prospects).
8. "Clear at a glance" cannot be judged properly from a description of a page; the text of the page was not supplied, so the pass rests on what the state note says, with the fresh reader as the check.
9. When the launch owner and the approver are the same person, the approval lines read oddly but work.
10. "Not supplied: none" is the natural reading for a first run, though input 10 (the last version) was not supplied; the template does not say whether to list it.

Nothing was sent, posted, published or switched on. This was one run in one product; it says the template can be followed on its example, not that it works in a client's environment.

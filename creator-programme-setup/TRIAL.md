# Creator programme setup: one run on its invented example

- **Product:** Claude, run in Claude Code
- **Model:** Claude Sonnet 5.5 (model ID claude-sonnet-5-5)
- **Date:** 2026-11-09

The inputs are the invented Larkmoor Tea Company example in `public/example.md`: the request, the founder's answers, the product list, the store figures and the cleared statements. No client data was used. The assistant that ran the template did not write it. It followed the instruction block and the output format in `member/template.md` on those five inputs, and read the example's own output only afterwards, to compare.

## Inputs used

- Input 1, the request: run date 2026-11-05, first run, run by the marketing lead with the founder present.
- Input 2, the founder's answers to sections 1 to 11, with the read-back already recorded as confirmed.
- Input 3, the product list exported 2026-11-04 (headers matched the five expected).
- Input 4, the store figures read 2026-11-02 by the operations lead.

## What was observed

The run produced every required part: all twelve sections, every line marked, the run report with the open items, the deal arithmetic at both ends of the margin band, the readiness lines and the log. It stopped for nothing. The headers matched, authority was stated, and the one instruction-like note in the inputs was recorded and not followed.

The template does exactly what it says on the points the example was built to test. The uncleared "Certified organic." went under Waiting to be cleared and not under Cleared. TikTok, which nobody had checked, stayed undecided and held back only work on TikTok. The arithmetic recomputes from the inputs shown. For the fee deal it gives a contribution of 21.60 and 26.40 and a cover of 13 and 11 tracked orders, matching the template's own acceptance test 7.

Where the instructions were ambiguous and a guess was needed:

- **Mark on the payout checks.** The output format ends the checked-on-the-path lines with `[owner]`, but step 2 says something read in the store is `[observed]`. These lines were read by the operations lead, not ruled by the owner, so the run used `[observed]`. The format line and the step disagree.
- **Mark on accepted proposals the owner restated.** Where the founder said "as proposed" the run used `[default]`. Where the founder restated a proposed value in their own words (exclusivity "none", the combining rule with free shipping added) the run used `[owner]`. The template does not say which applies when an owner repeats a proposal.
- **Brief readiness with two blockers.** The brief waits on the adviser's review and also cannot run for TikTok creators. The format offers "ready", "ready except for creators on" or "waits on", not both. The run wrote "waits on" and added the TikTok point in the same line.
- **Which deals get a fixed-cost row.** The founder asked for the fee and commission-and-fee comparisons only. The 18.00 product cost supports commission and gifted rows too, so the run added them. The template says "compare only if given" without saying whether a product cost given beside two deals applies to all four.
- **What 18.00 is.** The template calls it the cost of product sent. It equals the list price of the 100 g tin, not its cost. The run took the founder's figure as given and labelled it User-provided.
- **Currency in the minimum.** The shape is `minimum [amount]`. The run wrote "minimum 20.00 USD". It is unclear whether the currency belongs in it.
- **Disclosure for an undecided platform.** Section 8 needs a line for every platform allowed in section 3. TikTok is undecided, so the run printed no TikTok line. The template does not say whether a placeholder `[open]` line is wanted, and the "no line is dropped" rule could be read as asking for one.
- **Statement source.** Step 10 asks for the wording copied character for character with role and date. The output format has no place for where the wording came from (the label, the packing record), so that was dropped from section 7.
- **Log entry for a changed proposal.** The founder added two phrases to a forbidden line. The template asks for log entries for rulings that depart from a proposal, so the run logged it. It is not clear that adding to a proposal counts as a departure.
- **Interactive steps.** The template is written as a conversation, with proposals made section by section and a read-back. Here the founder's answers were already written down, so nothing was proposed live. The read-back line comes from the input's own last line ("confirmed every line as read"), not from a read-back done in this run.

Facts that are not in the inputs: none were added to the file. The example's "Instructions found" wording and the product list's two products left out are all from the inputs. One derived statement is the "no clash" check in section 5, which was done by comparing the pattern with the two live codes.

Differences from the published example's output are listed in the next section.

## Comparison with the published example

The published example's output and this run agree on every substantive point: the same cleared and waiting statements, the same open items (TikTok and the adviser's review), the same counts (2 open items, 1 statement waiting), the same readiness verdicts and the same arithmetic to the cent, including all four fixed-cost rows. The differences are small:

- **Roles.** The example writes "founder" for the owner; this run wrote "the owner", following the template's own role names. Both are roles, not names.
- **Payout checks.** The example marks the payout path and its checks `[owner]`, as the output format shows; this run marked them `[observed]` because they were read by the operations lead. The example also lists the plan check and the bulk-import check as two lines; this run joined them into one.
- **Products left out.** The example lists only the Cold Brew Starter Kit. This run also listed the Winter Gift Box, because the export marks it not active.
- **Code clash check.** The example says "no clash". This run named the two live codes it compared against.
- **Exclusivity.** The example marks "none" as `[default]`; this run marked it `[owner]`, because the founder stated it.
- **Log.** The example's first entry is by the founder; this run's is by the marketing lead with the owner present, which is who the request says ran it. This run added a third entry for the two phrases the founder added to a forbidden line. The example does not log that.
- **Wording.** Platform names are capitalised here and lower case in the example; the order of the fixed-cost rows differs; the run report's wording differs in places; "Decided today" in the example is a little more detailed on section 4 and section 7.
- **Facts not in the inputs.** Neither output adds a fact that is not in the inputs. The only derived statement in either is the "no clash" check, which is a comparison of the pattern with the two live codes the inputs list.

## Defects in the template

- The payout-check line in the output format says `[owner]`, which conflicts with the `[observed]` rule in step 2.
- Nothing says which mark applies when the owner restates a proposal in their own words.
- The brief's readiness line cannot hold two blockers at once.
- The template does not say whether a product cost given beside two deals applies to the commission and gifted deals as well.
- "Cost of product sent" is not defined, and the example's 18.00 is the list price of a tin.
- The output format has no place for the source of a cleared statement.
- The currency in "minimum [amount]" is not settled.
- An undecided platform's disclosure line is not specified.
- The "Reviewer checklist" and "Acceptance tests" are proposals that this run only partly exercised: it covered tests 1, 3, 5, 7 and 10 in effect, and not the others (headers renamed, discount ambiguous, requests to decline, revision run, names for roles).
- The template version note still says "Not yet tried on its invented example". That is now out of date for this run, though still true for client environments and other products.

## Edits made after this run (not run again)

The defects above were fixed in the template and the example on 9 November 2026, after this run. The edits below have not been run again. The run's output and observations above are left as recorded.

- **Payout checks.** The output format's checked-on-the-path line now ends `[observed]` (with `[open]` kept for a check not yet made), matching step 2. The published example's six payout checks, which were marked `[owner]`, are now `[observed]`, as this run marked them.
- **Restated proposals.** Step 2 and the pasted instructions now say `[default]` is a proposal accepted by reference ("as proposed") or word for word, and a value the owner states in their own words, even one matching a proposal, or a proposal the owner adds to, is `[owner]`. The example's exclusivity line, which the founder typed as "Exclusivity: none", is now `[owner]`.
- **Brief readiness with two blockers.** The readiness lines now offer "waits on: [items]; also not for creators on [platform]". The example's brief line uses it.
- **Which deals get a fixed-cost row.** The template now says a product cost given applies to every deal that sends product.
- **What 18.00 is.** The template now defines the cost of product sent as what the brand pays for the product and its shipping, not its list price. In the example, the founder's answer now says the product sent to one creator costs the brand 18.00, shipping included. The figure and every result are unchanged.
- **Statement source.** Section 7 of the output format now carries the source of each cleared statement on an indented line beneath it, so the statement line keeps the shape the creator brief reads. The example shows the tin label and the packing record.
- **Currency in the minimum.** The shape is now `minimum [amount] [currency]`; the example writes "minimum 20.00 USD", as this run did.
- **Disclosure for an undecided platform.** Step 11 and the pasted instructions now say a platform ruled `no` or `undecided` gets no section 8 line; its open item stays in section 3.
- **Log entries.** Step 15 now says adding to a proposal counts as a departure, and each entry names the role who ruled and, when someone else ran the session, the role who ran it. The example's log now names the founder and the marketing lead in that way and has an entry for the two phrases added to the first forbidden line, as this run logged them.
- **Smaller wording changes.** The template and the profile now say the file supplies the rules the three other creator workflow templates take as inputs, and note that a platform this file leaves `undecided` is one the vetting shortlist calls `unknown`. The proposal to turn on the platform's own partnership label beside the written label is now worded as the owner's ruling. The version notes and the public profile now say the template was tried once on its invented example.
- **Acceptance tests.** Test 7 now calls its 18.00 the cost of product sent; its figures are unchanged. The tests this run did not exercise are still unrun.
